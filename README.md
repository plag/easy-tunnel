# EasyTunnel

Node.js-клиент для собственного сервера EasyTunnel. Делает локальный HTTP-сервер доступным по HTTPS и поддерживает WebSocket, в том числе Vite HMR. Для использования нужен Node.js 18.17 или новее и токен сервера.

## Установка

После публикации репозитория добавьте зависимость в проект:

```bash
npm install --save-dev github:plag/easy-tunnel
```

Или добавьте в `package.json`:

```json
{
  "scripts": {
    "tunnel": "easytunnel --src=5173"
  },
  "devDependencies": {
    "easytunnel": "github:plag/easy-tunnel"
  }
}
```

Создайте `easy-tunnel-config.json` в корне своего приложения:

```json
{
  "server": "https://tunnel.example.com",
  "token": "ваш_токен"
}
```

Токен выдаёт администратор сервера. Добавьте `easy-tunnel-config.json` в `.gitignore` своего проекта: файл содержит секрет. Не публикуйте токен и не отправляйте его в общий чат. При необходимости можно явно задать `TUNNEL_TOKEN` через окружение — он имеет приоритет над токеном из конфига. Проектный `.env` клиент не читает.

В конфиге можно также задать параметры по умолчанию:

```json
{
  "server": "https://tunnel.example.com",
  "src": 5173,
  "token": "ваш_токен",
  "preserveHost": false
}
```

Адрес сервера и токен обязательны: укажите `server` в конфиге или аргументом `--server`, а токен — в конфиге или переменной `TUNNEL_TOKEN`. `src` — номер локального порта; его можно указать в конфиге или через `--src`. Параметры CLI `--src`, `--server` и `--preserve-host` имеют приоритет над конфигом. Шаблон есть в `easy-tunnel-config.example.json`.

## Тестовая группа VK Mini Apps

Чтобы при подключении обновлять адрес существующей тестовой группы, добавьте в `easy-tunnel-config.json` сервисный токен приложения и точное имя группы. Например, для группы `s` конфиг выглядит так:

```json
{
  "server": "https://tunnel.example.com",
  "src": 5173,
  "token": "YOUR_TUNNEL_TOKEN",
  "vkServiceToken": "YOUR_VK_APP_SERVICE_TOKEN",
  "testGroupName": "s"
}
```

После подключения CLI выводит публичный URL в stdout. В stderr появится статус с именем группы и адресом, например `Тестовая группа «s»: URL обновлён — https://dev.tunnel.example.com`. Если адрес уже совпадает, CLI сообщает об этом. При ошибке VK или неоднозначном имени CLI выводит причину и продолжает обслуживать туннель.

## Запуск

Запустите локальный dev-сервер и в другом терминале:

```bash
npm run tunnel
```

Клиент выведет публичный HTTPS-адрес. Порт `5173` в `package.json` можно заменить на порт вашего приложения. Команда также доступна через `npx easytunnel --src=5173`.

Адрес сервера можно задать в конфиге или явно при запуске:

```bash
npx easytunnel --server https://tunnel.example.ru --src=3000
```

Клиент пробует `127.0.0.1` и `::1`. Чтобы Vite работал без изменения конфигурации, локальный запрос получает `Host: localhost:<порт>`, а публичное имя передаётся в `X-Forwarded-Host`. Если приложению нужен исходный заголовок `Host`, укажите `--preserve-host`. Тогда может потребоваться разрешить домен в dev-сервере.

По умолчанию клиент подключается к серверу напрямую и предупреждает, если в окружении заданы переменные прокси. Чтобы использовать `HTTPS_PROXY` или `ALL_PROXY` (также поддерживаются варианты в нижнем регистре) и учитывать `NO_PROXY`, запустите клиент с флагом:

```bash
npx easytunnel --src=5173 --use-proxy
```

С `npm run tunnel` дополнительный параметр передаётся через `--`: `npm run tunnel -- --use-proxy`. Если подходящий прокси не задан или сервер включён в `NO_PROXY`, соединение будет прямым. Настройка относится к подключению клиента к серверу; браузер использует собственные настройки сети.

Публичный URL позволяет любому, кто его знает, обращаться к локальному приложению. При отключении туннеля клиент завершается; повторный запуск выдаёт новый URL.

## Совместимость

Клиент использует протокол EasyTunnel версии **1**. При подключении он проверяет версию, сообщённую сервером, и сообщает об ошибке, если сервер несовместим или не сообщает версию. Это не версия npm-пакета.

Для разработки клиента в этом репозитории установите зависимости и запустите локальную версию:

```bash
npm install
npm run dev -- --src=5173
```

Клиент читает `easy-tunnel-config.json` из текущего каталога. Сначала запустите приложение на выбранном порту. Двойной дефис перед `--src` нужен команде npm, чтобы передать параметр клиенту.

Для другого сервера:

```bash
npm run dev -- --server https://tunnel.example.ru --src=3000
```

При прямом запуске через `npx` дополнительный дефис не нужен. Для совместимости по-прежнему поддерживается позиционный порт, например `easytunnel 5173`.

Для запуска тестов используйте `npm test`.
